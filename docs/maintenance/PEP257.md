# Python docstring conventions

Use Ruff 0.14.1 with the `pep257` convention and the existing PEP 8 configuration.
Install requirements-style.txt, then run `python -m ruff check .` and
`python -m ruff format --check .`. The D family is included in the normal check.

Use triple double quotes, a concise imperative summary for operations, and a
blank line before any extended explanation. Describe contracts, failure behavior
and important side effects from the implementation; do not infer guarantees from
names or type annotations. Plain prose is preferred over redundant argument lists.

Document public modules, classes, functions, methods and constructors. Explain
non-obvious private behavior. A framework override may refer to the documented
base contract, but provider-specific restrictions still need documentation.
Trivial tests do not require repetitive prose: any missing-docstring exceptions
must be narrowly scoped and justified here. Existing docstrings remain subject to
formatting checks. There are currently no new missing-docstring exceptions.

The .ci directory is the existing temporary checkout exclusion, not maintained
source. This initiative adds no generated/vendor exclusions. Preserve existing
Calibre UP exceptions; its earlier D exclusions for application modules are removed.

Module docstrings used as argparse descriptions are runtime help contracts.
Review changes to them separately. Preserve future imports and executable ASTs.
Docstring text is intentionally observable through __doc__; no business logic,
SQL, request behavior, release pins or production configuration may change.

The initial audit uses isolated D rules with this same convention so earlier
repository exclusions cannot hide violations. Lint measures structure, not semantic
accuracy. Semantic review and regression results must be recorded separately.
